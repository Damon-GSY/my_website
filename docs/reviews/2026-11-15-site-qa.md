# Whole-site QA pass, 2026-11-15

Build: `npm run build`, served with `vite preview` (port 4271). Playwright + Chromium. Each route was loaded at 1440x900 and 390x844 in three modes:

- **gl**: WebGL on (SwiftShader), normal motion
- **reduced**: WebGL on, `prefers-reduced-motion: reduce`
- **no-gl**: `--disable-webgl --disable-3d-apis` (only for the WebGL pages: `/`, `/parcel`, `/descent`, `/rollout`, `/d20`, `/lab/night/`, `/lab/paper/`)

For every run the script recorded console errors, page errors, failed requests and horizontal overflow (`scrollWidth - innerWidth`). It also took a screenshot of the first viewport and one at mid-page. All screenshots went into contact sheets and were looked at. Keyboard: on `/` and `/lab`, the first 16 Tab stops all show a 2px solid outline (`:focus-visible`).

Result: no page errors, no failed requests and no horizontal overflow on any route except the concept boards (by design, see below). In no-gl mode the only console output is three.js's own "could not create a WebGL context" message. Every WebGL page then shows a readable static fallback, not a blank page.

Build: no chunk changed size apart from `Home` (21.5 → 20.2 kB) and a new `WorkFilm` chunk (2.3 kB). The entry is still 246.7 kB / 78.9 kB gzip with no three in it.

Changes:

- `src/pages/Home.jsx`: `WorkFilm` is now `React.lazy`. The Parcel film and the D20 chapter sit in a `Deferred` wrapper that mounts them when they come within one viewport (IntersectionObserver, `rootMargin: 100%`). Until then a blank block of the film's own scroll length (700vh, 600svh) holds the place, so section offsets are the same before and after mounting: work 1895, evaluate 8195, path 14554, contact 17975 px. With reduced motion, no WebGL or no IntersectionObserver the chapters mount right away, because their static fallbacks are short. The lens studies were already lazy and only load when a lens is chosen.
- `src/directions/ink/InkHero.jsx`, `ink.js`: the loop's twin `<video>` is `preload="none"` until the first copy fires `canplaythrough`. Both copies were checked at readyState 4 after a scroll-through, so the loop still works.
- Concept boards: `public/lab/concepts/fit.css` and `fit.js` are linked from all 8 boards, and the viewport meta is now `device-width`. The board is scaled by `min(w/1600, max(h/1000, 0.45))` and centred, and the scale is recomputed on resize. A short window keeps 0.45 and scrolls vertically instead. A narrow phone fits the width with no horizontal scroll. The drawings are unchanged.

Verified: a scroll-through contact sheet at 1440x900 (hero, Work, D20, Path, Contact). Clicking the #work and #evaluate nav links on a fresh page lands each chapter at top = 0. Reduced motion and no-WebGL both render the static Parcel and D20 fallbacks. The concept boards were checked at 1440x900, 390x844 and 1200x400. There were no console errors except THREE's "could not create a WebGL context" warnings under `--disable-webgl`, which come from the films' own no-WebGL path.
