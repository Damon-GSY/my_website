# Whole-site QA pass, 2026-11-15

Build: `npm run build`, served with `vite preview` (port 4271). Playwright + Chromium. Each route was loaded at 1440x900 and 390x844 in three modes:

- **gl**: WebGL on (SwiftShader), normal motion
- **reduced**: WebGL on, `prefers-reduced-motion: reduce`
- **no-gl**: `--disable-webgl --disable-3d-apis` (only for the WebGL pages: `/`, `/parcel`, `/descent`, `/rollout`, `/d20`, `/lab/night/`, `/lab/paper/`)

For every run the script recorded console errors, page errors, failed requests and horizontal overflow (`scrollWidth - innerWidth`). It also took a screenshot of the first viewport and one at mid-page. All screenshots went into contact sheets and were looked at. Keyboard: on `/` and `/lab`, the first 16 Tab stops all show a 2px solid outline (`:focus-visible`).

Result: no page errors, no failed requests and no horizontal overflow on any route except the concept boards (by design, see below). In no-gl mode the only console output is three.js's own "could not create a WebGL context" message. Every WebGL page then shows a readable static fallback, not a blank page.
