“知之为知之，不知为不知，是知也。”

《论语·为政》1

为什么收藏了那么多资料、买了那么多课程、记了那么多笔记，遇到问题时还是不会用？

课没少买。以前学计算机时，前端还没学完，我又开始看后端和 Spring Boot，接着买了一系列视频课程。到了做作业和项目的时候，我仍然要去 CSDN 搜函数和教程。课程列表越来越长，我对眼前的问题却没有更清楚。

后来我换了一个顺序。开始学习一件事，先承认自己站在哪里。哪些内容已经能够解释和使用，哪些明确不知道，还有哪些只是看起来熟悉，我其实拿不准。这个判断给了我一个起点，也留下了改图的余地。

学习，是围绕真实问题选择值得掌握的内容，画出自己的认知结构，再用行动和反馈不断修改它。

我把这个过程暂时整理成一条“认知映射循环”。

选择 → 建构 → 应用 → 反馈 → 修正

一 选择

从那批没有学完的课程里，我先得到一个很朴素的结论。时间和注意力有限，选了一项能力，其他可能性就得暂时让开。学习也包括放下一些当下用不到的东西。

开始学习一个主题之前，我现在会问五个问题。

  1. 这项能力和我眼下的工作、生活或真实问题有什么关系？
  2. 我需要亲自使用到什么深度，又会多频繁地使用？
  3. 如果完全放弃，我是否愿意承担相应的结果？
  4. 合作、工具或专业人士能否补上这项能力，我只保留沟通和判断结果所需的基础理解？
  5. 亲自学习仍然是当前最合适的选择吗，我下一步能做的最小行动是什么？

问完以后，一项能力通常会落入三种结果。现在深入学习，只掌握协作所需的基础，或者明确地暂时不学。买下一门课程，只说明我为一种可能性付了钱。

舍弃没有关掉未来的路，只是承认当前资源有限，先把时间交给眼下更重要的问题。目标、环境或职责变了，我可以重新选择。

这里所说的“真实问题”不必来自工作。一次考试、一项生活选择、一个真心想弄懂的问题，都可以成为学习的起点。好奇心也足够。关键在于，我能说清楚为什么愿意把注意力交给它。

把“想学”改写成任务

决定投入以后，我还会判断自己最终需要完成什么。不同任务会调用三类知识。2

知识类型要回答的问题任务怎样检验它
声明性知识（Declarative Knowledge）它是什么，为什么如此？能解释事实、概念、机制和关系
程序性知识（Procedural Knowledge）它应该怎么做？能执行、推导、解题、测试和调试
条件性知识（Conditional Knowledge）什么时候应该这样做？能根据目标、限制和代价选择策略

数学、编程、历史和经济学都可能同时用到这三类知识。单凭学科名称，很难判断应该怎样学。最终任务会告诉我需要解释什么、执行什么，还要在哪些条件下作出判断。条件性知识尤其接近工作中的判断力，同一种方法换了时间、预算或风险要求，选择也可能跟着变。

任务也会决定记忆需要多准确。闭卷作答、限时推导和即时执行，都要求快速而准确地提取信息。工作与日常学习常常允许查阅资料，AI 又让查找和解释快了许多。在这些场景里，我会把更多注意力放在定义问题、选择方法和验证结果上。需要记到什么程度，应当由使用场景和考核方式来决定。

二 建构

先画出来。

选好问题以后，我会先把已有的理解画出来。这张 Mind Map V1.0 带着过去的经验和判断，可能粗糙，也可能有错，但它诚实地记录了我此刻怎样理解这件事。

我所说的 Mind Map

传统树状图擅长分类。一个主题有哪些部分，层级怎样展开，它能交代得很清楚。可我学习时更关心另一类关系。两个分支怎样互相影响，一个结论依赖哪些条件，一条新信息又会改动图上的什么地方。

因此，我所说的 Mind Map 更接近一张非线性的认知关系图。概念是节点，连线保存关系，箭头可以表达影响、依赖和流动。同一个概念也可以连接个人经验、支持它的证据、相反观点和适用边界。

一张 Mind Map 应该忠实地画出我当前怎样思考。课程目录、书本章节和标准答案只能提供参考。

这张图不需要固定模板，我也不会为了显得严谨，另外设计一套标记去表示“不确定”和“不知道”。它只画已经形成的知识关系，同时提醒我，图上没有出现的东西仍然可能存在。

把脑中的关系画出来

开始学习时，我会先在 iPad 上画一张临时 Mind Map，把正在解决的问题和眼下注意到的概念写进去。已经形成的连接、影响方向和过去经验，随后再补。

图不必漂亮，也不必完整。画图这个动作会把脑中原本模糊的关系放到眼前。即使后来证明某条连接错了，V1.0 依然有用。没有这张快照，我很难说清自己的判断究竟从哪里开始变化。

下面这张图，是我学习大模型相关内容时留下的一张临时认知结构。

这张图记录了当时的思考。读者不需要理解里面的技术术语，只需要观察连接、方向和知识流动怎样被表达。

我过去更常写下面这样的线性笔记。

定义、公式和性质按照书写顺序依次展开。

这页二重积分笔记就是我过去最常用的写法。定义、性质和公式跟着老师的讲解顺序往下记，每一条都可能是对的，也方便以后查推导。可我想知道一个条件会怎样改变结论，或者两个概念为什么连在一起时，就得重新在不同段落之间寻找。

再看前面的大模型图。教师模型、学生模型、知识蒸馏、训练方法和评价方式没有被分开放进几棵树里。箭头标出作用方向，分支拆开概念，并列节点帮助比较方法，公式又把抽象概念接到具体计算上。节点多少没有那么要紧，连线能不能说清楚才要紧。

图用来看整体关系，线性内容负责讲清局部。我需要两种笔记，只是不会再用一页写得很满的线性记录，代替脑中尚未形成的关系。

收藏以后，学习还没有开始

现在收集信息太容易了。看到文章、书或视频，点一下按钮，它就进入了收藏夹。我也收藏过大量内容，后来真正重新打开的很少。

收藏的那一刻会让人安心。这条信息没有丢，以后还能处理。新的内容不断出现，“以后再看”也就渐渐没有了下文。

收藏按钮替我保存了链接，也让我提前结束了对这条信息的处理。这个动作很轻，轻到我经常把“没有丢”当成“以后会学”。

笔记会把信息留在大脑之外，这个作用很有价值。不过，写下文字没有自动建立知识关系。笔记之间有链接，软件里能生成复杂的关系图，也无法证明我的脑中已经形成同样的结构。

老师、课程、书籍和 AI 给出的解释可以影响我，却不会直接成为我的理解。我需要判断它改变了哪个节点，补上了哪条关系，又和已有经验发生了什么冲突。到了这一步，外部信息才开始进入个人认知结构。

我主要用 Obsidian 建立个人知识库，协作和结构化管理则会用 Notion。对工具选择有疑问，可以看我做过的对比视频。3 工具能减少摩擦，认知深度仍然取决于我怎样处理信息。

用压缩找到 Anchor Point

把思考画成网络，也要克制往图里堆节点。没有主次和关系，Mind Map 很快会变成另一份资料清单。

这张树状图能看到分类层级，却没有呈现训练方法与评价方式怎样跨过分支影响其他节点。

我把自己的判断概括成 “理解即压缩”（Understanding is Compression）。理解会从大量信息中提取较为稳定的结构，用较短的描述解释更多事实。压缩帮助我挑出核心节点，找到可以反复连接新知识的 Anchor Point。

压缩太少，图上只剩案例和细节，很难迁移。压缩过头，图上又只留下一句空话，关键条件和差异都丢了。好用的压缩要经得住解释和应用。

接触新概念时，我会先找 Big Picture，再沿着几个问题寻找骨架。

  • 它为什么值得我现在学习？
  • 它原先想解决什么问题？
  • 它和我已经知道的哪些概念有关，和相似概念又差在哪里？
  • 它依赖什么前提，到了什么情况会失效？
  • 它位于整个领域的什么位置？

定义、公式、代码和步骤依然重要。它们有了可以依附的节点和关系，回忆时也更容易找到。图是否简单并非判断标准，我更在意留下的结构能否帮助自己解释问题，并在下一次反馈到来时继续修改。

三 应用

然后去用。

画完图，我会尽快拿它去做事。开始解释、推导、写作或行动以后，我才知道图上的知识能不能被调用。

把非线性的图展开

Mind Map 可以同时保留许多方向，表达却必须选一条路。从哪个节点出发，哪条关系先讲，怎样走到下一个概念，这些都需要我自己决定。

写作很适合做这个检查。它会把脑中的关系图沿着阅读顺序铺开。两个节点之间接不上，一个结论突然跳出来，或者离开原文就讲不下去，都说明当前的图还撑不起这次表达。

这和常被称作“费曼学习法”的自我解释有相通之处。我更在意关系能否被完整展开。讲得简单当然很好，前提是关键关系没有在简化时丢掉。

Bloom 修订版认知分类也提供了一把检查任务的尺子。4

这张常见的金字塔呈现了认知过程复杂度的大致差异。修订版原著还有知识维度，也没有要求每项任务都严格逐级通关。

认知过程关键动作可以观察到的结果
记忆（Remember）识别、提取能提取事实、术语和定义
理解（Understand）解释、举例、分类、概括、比较能用自己的语言说明关系与机制
应用（Apply）执行、实施能把知识用于一个具体问题
分析（Analyze）区分、组织、归因能发现组成、关系和原因
评价（Evaluate）检查、批判能依据证据与条件解释取舍
创造（Create）生成、规划、产出能形成新的解释、模型或方案

六类认知过程大体存在复杂度差异，也会重叠。用它检查任务，比把它当成固定升级路线更合适。

前面提到的“什么时候应该这样做”，主要会调用应用和评价。我要执行方法，也要看它是否适合当前条件，并解释自己接受了什么代价。

单独把记忆设为目标，我很容易平均用力地背下大量细节。换成完成一次应用、分析或创造，任务会把我送回基础概念。哪些内容必须准确提取，哪些关系仍然模糊，这时都会暴露出来。

尽快进入真实任务

对我帮助最大的学习经历，往往来自直接做作业和项目。输入到这里会突然变得不够用，我得把知识调出来，放进一个有结果的任务里。

以初学编程为例。学会 for 循环、if 条件语句和基本语法后，可以给自己一个很小的任务，写一个求职进度管理程序。它遍历职位记录，按照投递状态和面试日期分类，再提醒哪些岗位需要跟进。

每个语法点单独看都不复杂，放到一起就得处理数据结构、条件组合和异常输入。为了把程序做完，我会主动回去补语法和概念。此前自以为懂了的地方，也会在运行结果里露出缺口。

我自己的节奏通常是先看一个完整示例，完成边界清楚的练习，随后尽快进入规模可控的真实任务。等到完全准备好，项目多半永远不会开始。

让记忆服务于任务

有些任务要求准确而快速地提取事实、术语、公式或步骤。Anki 可以用卡片练习主动提取，再根据作答情况安排复习。

Anki 会安排重复，却无法替我选择内容。用法只剩按时点按钮时，它就成了一个更方便的 repetition 管理器。一张卡片答对了，也只证明这次能够提取，理解、迁移和判断还要放进别的任务里检验。

我现在会从未来的使用场景倒推。闭卷或限时任务需要哪些内容随时调用，哪些内容只要理解关系，需要时又有哪些细节可以查阅。这样做，记忆有了服务对象，也不必平均覆盖所有信息。

四 反馈

我所说的反馈范围很宽。一本书里的解释、他人的问题、与原有理解冲突的事实，都可能改变当前的 Mind Map。练习答案、程序运行结果和现实行动带来的回应，也在其中。

接触一条新信息时，我们通常还不知道它最终会被证明正确或错误。按照这里的定义，它一旦改变了原来的图，学习就已经发生；这次变化有没有让理解更接近现实，还要等待后面的证据和检验。错误信息也可能改动这张图，只是后续修正要付出更多代价。

应用的价值在这里很具体。写作会暴露关系断点，推导数学题会让我看见公式该怎样使用，程序则直接给出运行结果。真实行动带来的反馈往往更直接，因为现实不会配合我维护一张画错的图。

AI 缩短了反馈回路

以前学习编程，我经常去搜索引擎和 CSDN 找函数、报错和教程。现在可以把困惑直接交给 AI，让它解释一段代码，追问一个概念，或者帮我找出推理里的断点。

答案来得快，也更容易让人跳过思考。我更愿意在卡住的时候追问 AI，让它解释为什么、比较两种方法，或者只给下一步提示；随后由我继续做，并检查结果。它缩短了从困惑到解释的距离，解释后面的判断和行动还得由我完成。

用问题检查自己的图

面对刚学到的概念，我会试着回答下面的问题。

  1. 离开材料以后，我能用自己的话解释它吗？
  2. 它和哪些旧概念相连，又最容易和什么混淆？
  3. 它成立需要哪些条件，什么时候会失效？
  4. 我能把它用到一个没见过的问题上吗？
  5. 出现什么证据，我会修改现在的理解？

这份问题表不用每次逐项打勾。它只是把注意力从“我完成了多少学习动作”拉回认知结构。答不上来的地方，就是下一轮该处理的地方。

五 修正

错了就改。

完美主义很容易让人不断增加输入。总觉得材料还没读完，背景还没掌握，自己的判断也就迟迟不肯出现。结果是收藏越来越多，理解一直没有机会接受检验。

我现在把 Mind Map V1.0 当作一份可以修改的先验。它来自已有经验，只对当前版本负责，后面的信息随时可以改动它。

新信息进入以后，图上的节点、关系或确信程度发生变化，V2.0 就形成了。它是这一轮的后验，也会成为下一轮的先验。

前面那张大模型认知图记录的就是某一刻。后来的解释、应用结果和反例，都可能让我增加节点，删掉没有依据的连接，或者改变概念之间的方向。有时局部修改已经够用，有时整张图都要重画。

我希望这张图能够稳定，也能修改（solid but revisable）。它要有足够稳定的 Anchor Point，让新知识很快接到已有节点上；同时给未知信息留出改图的权利。我不需要事先承诺当前结构永远成立。

新知识一旦接入已有关系，通常也更容易记住。回忆时，我可以沿着问题、节点和连线重新找到它，不必把每条信息孤立地保存。

图上没有“不确定”的专用符号也没关系。我们无法提前画出尚未意识到的盲区，只要记得 V1.0 是一张开放的图，就还有继续修改的空间。

改变看法说明旧图遇到了新证据。一次方法得到的结果，也只评价这次尝试，不能替一个人的潜力下最终结论。

让五个动作继续循环

完整过程可以写成下面这样。

选择　判断是否值得学，并定义真实问题
→ 建构　把已有先验画成非线性的 Mind Map V1.0
→ 应用　通过语言、写作、推导或行动展开这张图
→ 反馈　让新信息影响当前先验
→ 修正　更新节点和关系，形成 V2.0

V2.0 会成为下一轮的先验。我可能回到建构，重新画出已经变化的关系；也可能再次应用，主动获得新的反馈。继续投入已经不值得时，就回到选择。
